# Inecat 猫咪照片社区升级包

这是一个独立于现有静态站点的社区组件。现有 Nginx 继续提供原有网页、图片和视频；新组件提供注册、登录、上传、照片元数据和用户管理。照片仍保存在文件系统，MySQL 只保存账号、会话和照片记录。

## 分阶段实施

1. **本地审阅**：阅读本文件和 `DEPLOYMENT.md`，确认目录规划。当前工作区没有原站点源码或服务器配置，因此没有覆盖原文件。
2. **隔离试运行**：复制本目录到测试主机，用单独端口和测试域名验证。初始管理员由交互式命令创建，不提供默认密码。
3. **备份与上线**：确认生产备份可恢复后，先备份 Nginx 配置和网页目录，再部署容器及独立数据目录；最后才按部署说明添加三个精确匹配的 Nginx 路由。
4. **上线后维护**：定期备份 MySQL 与上传目录，检查磁盘、容器日志和 Nginx 日志，及时更新镜像和依赖。

现有站点中的图片、视频不会被移动、覆盖或自动导入数据库；它们继续由现有静态站点按原 URL 提供。社区画廊显示新上传的社区照片。由于当前工作区没有原站点目录清单，尚不能把旧图片集合纳入新画廊索引，也没有修改旧首页添加入口；部署时可在旧首页加一个指向 `/community/` 的链接。不要为导入而扫描不确定的服务器目录。

## 本地试运行

需要 Docker Compose。复制 `.env.example` 为 `.env`，填入随机生成的强数据库密码、会话密钥和 CSRF 密钥；不要把 `.env` 提交到 Git。生产环境不能直接使用示例值。

```bash
docker compose up -d --build
docker compose exec api python -m app.cli create-admin
```

测试时可临时把 Nginx 路由接到本机 8080；不要把 8080 暴露到公网。生产路由配置、备份、恢复、首次管理员创建和回滚步骤见 `DEPLOYMENT.md`。

## 权限设计

- 未登录用户可以查看全部公开照片；登录用户可上传。
- 普通用户的更新和删除 SQL 同时限定 `photo_id` 与当前 `owner_id`。知道其他照片 ID 或 URL 也不能越权。
- 管理员可管理所有照片，并可停用普通账号；管理员身份在每次请求时从数据库读取，不信任客户端角色字段。
- 密码使用 Argon2id 哈希；会话令牌随机生成，只以 SHA-256 摘要存储，并支持服务端撤销及过期。
- 所有变更请求要求会话绑定的 CSRF 令牌；Cookie 使用 HttpOnly、SameSite=Lax，线上强制 Secure。
- 上传限制为 10 MiB，允许 JPEG/PNG/WebP，经 Pillow 解码验证并重新编码，剥除 EXIF；文件名由 UUID 生成，不采用用户提供路径。
- Nginx 上传目录设置为只读静态访问，应用只负责写入；不接受 SVG、视频、任意文件或可执行内容。

## 管理员权限

首次管理员只能由在服务器上有容器管理权限的人通过 `create-admin` 创建。该命令要求交互输入用户名和密码，仅在管理员数为零时成功。普通用户注册不能自行获得管理员角色。管理员可以停用账号并管理所有照片；不会显示或输出任何默认密码。

更多运维命令及 Nginx 配置说明见 `DEPLOYMENT.md`。
